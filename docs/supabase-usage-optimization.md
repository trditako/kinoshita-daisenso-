# Supabase利用量の一時抑制

2026-10-12時点でFreeプランの利用上限を超過し、Edge FunctionがHTTP 402を返していたため、リセット日までの不要な通信・ログを抑制する。

## すでに適用したDBスケジュール変更

- `ai-worker-2min`（jobid 1）を一時停止。上限超過中に5分ごとに失敗していたAI worker呼び出しを止める。
- `kinoshita-rank-reset`（jobid 2）を毎分から15分ごとに変更。リセット判定を維持しつつcronの実行・ログを削減する。

利用上限がリセットされ、Edge Functionが正常応答することを確認した後、AI workerを再開する。

```sql
select cron.alter_job(job_id := 1, active := true);
```

## クライアントの通信量削減

- AIアカウント一覧取得で `select=*` を使わず、一覧・戦闘処理に必要な列のみを取得する。対戦履歴・活動履歴の全件転送を避ける。
- AI worker状態のポーリングを15秒から60秒へ変更し、ページが表示中かつランク画面表示中に限定する。
- ワールド告知とイベント状態のポーリングを45秒から120秒へ変更する。タブが非表示のときは告知取得をスキップする。

## 注意

利用量の削減を目指す変更であり、次回リセットまで絶対に上限を超えないことを保証するものではない。Supabaseの使用量画面でEgressとLog Ingestionを定期的に確認する。
